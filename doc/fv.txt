How we can use finite volume (fv) in nmesh?
===========================================

Grid setup
==========

With standard dg we have non-uniform grid points in a node, e.g. like this:
o  o      o             o             o      o  o

For fv we 1st change the node grid points to e.g:
o       o       o       o       o       o       o

We then define midpoints (i.e. in the middle between grid points)
at which we need to need to reconstruct the fields so that we can get the
fluxes there. This would give:
o   |   o   |   o   |   o   |   o   |   o   |   o
                    <-- h -->
If d_t u = RHS = -d_x f
Then u at an interior point i, has a RHS of the following form:
RHS_i = -(f*_{i+1/2} - f*_{i-1/2})/h
here h is the distance between the 2 midpoints around point i.
                i
o   |   o   |   o   |   o   |   o   |   o   |   o
           /   u_i   \
          /           \
      f*_{i-1/2}       f*_{i+1/2}
Note, RHS_i is the quantity that would be the divergence of the flux in the
dg method.
RHS_i = -(f*_{i+1/2} - f*_{i-1/2})/h works for all interior points.

The points at the ends of the node are dealt with differently!
First we interpret the final points to be moved in by h/4, so that we get e.g.:
| x |   o   |   o   |   o   |   o   |   o   | x |
I.e. we now have another fv-element at the ends of the node.

So to update e.g. u_0, we now need the fluxes at f*_{1/2} and f*_{-1/2}:
d_t u_0 = RHS_0 = -(f*_{1/2} - f*_{-1/2})/(h/2)
| x |   o   |   o   |   o   |   o   |   o   | x |
|    \
|     f*_{1/2}
f*_{-1/2}
f*_{-1/2} can be constructed with the help from info from the node to the
left. f*_{1/2} can be constructed with information from within the node.


Flux reconstrution in the interior at e.g. at i+1/2
===================================================

*At 1st order (i.e. with error of O(h)):
Def:   up_{i+1/2} := u_{i}               um_{i+1/2} := u_{i+1}
       The function that gets up_{i+1/2} is rec1d_p_1.
Then:  fp_{i+1/2} = f(up_{i+1/2})        fm_{i+1/2} = f(um_{i+1/2})

fp_{i+1/2} and fm_{i+1/2} are two ways to reconstruct the flux at i+1/2.
In order to get the numerical flux f*_{i+1/2} we then use e.g. the LLF flux,
to calculate f*_{i+1/2} from
[inside: (up_{i+1/2}, fp_{i+1/2}), adjacent: (um_{i+1/2}, fm_{i+1/2})]

*At 3rd order (i.e. with error of O(h^3)):
Get fp_{i+1/2} and fm_{i+1/2} from e.g. rec1d_p_WENO3 and rec1d_m_WENO3.
Note: rec1d_p_WENO3 and rec1d_m_WENO3 only work if i>1 and i>0.
Again we can use e.g. LLF to get f*_{i+1/2}.

Flux reconstrution in the interior close to surface at e.g. at 1/2
==================================================================

*At 1st order (i.e. with error of O(h)):
Def:   up_{1/2} := u_{0}               um_{1/2} := u_{1}
       The function that gets up_{1/2} is rec1d_p_1.
Then:  fp_{1/2} = f(up_{1/2})        fm_{1/2} = f(um_{1/2})
Again we can use e.g. LLF to get f*_{i+1/2}.

Flux reconstrution at the node surface e.g. at -1/2
===================================================

*At 1st order (i.e. with error of O(h)):
Def:   up_{-1/2} := u_adj <- val from node to left
Def:   um_{-1/2} := u_{0}
       The function that gets um_{-1/2} is rec1d_p_1, u_adj it sent via MPI.
Then:  fp_{-1/2} = f(up_{-1/2})        fm_{-1/2} = f(um_{-1/2})
Again we can use e.g. LLF to get f*_{-1/2}.
[inside: (um_{-1/2}, fm_{-1/2}), adjacent: (up_{-1/2}, fp_{-1/2})]

= Some more notes about fv and WENOm3_2 =
=========================================
First of all, WENO works much better on a uniform grid. That is why

      if(DGglobals->fv_rec_mode >= FV_REC_WENO3if2away_1)
        rec1d_uface_to_uin_1(node, vlu, 1);

in scalarwave1_set_divf is usually inactive before calling fv_divf. I.e. we
do not interpolate to the point x first.
o x |   o       o       o       o       o       o

Rather we keep the grid as:
 0       1       2       3       4       5       6 <-- gridpoint number i
 o   |   o   |   o   |   o   |   o   |   o   |   o
     0       1       2       3       4       5     <-- midpoint number im
-1                                               6 <-- facepoints: im=-1, im=6

We can use e.g. rec1d_p_WENOm3_2 and rec1d_m_WENOm3_2 to reconstruct u at the
interior midpoints from the points to the left and right. Points near or at
the boundary are more complicated.  We can reconstruct like this:

 |u l|mW   pW|mW   pW|mW   pW|mW   pW|mW   pW|l u|
 o   |   o   |   o   |   o   |   o   |   o   |   o

Here:
 -pW: use rec1d_p_WENOm3_2 to reconstruct u
 -mW: use rec1d_m_WENOm3_2 to reconstruct u
 -l: use linear interpolation using the gridpoints (o) to the left and right
 -u: use the value of u at the gridpoint (o) at the node boundary

So for interior midpoints (im=0-5) we have a left and right value for u,
i.e. up and um. From these 2 we can then get the 2 fluxes fp and fm.
From fp and fm we calculate the numerical flux f* using e.g. LLF.
Then we have:
i=0     i=1     i=2     ...
 o   |   o   |   o   |   o   |   o   |   o   |   o
    /        \
   /          \
 f*_{im=0}   f*_{im=1}   ...

From f* at (im=0-5) we can then get divf = dx f on all interior
gridpoints (i=1-5). I.e. for i=1,2,...,5 we use:

divf_{i} = (f*_{im} - f*_{im-1})/h ,    where im = i.


The boundary gridpoints (i=0 and i=6) are different:
----------------------------------------------------
The vol RHS calculation calls fv_divf which sets

divf_{i=0} = f*_{im=0} / (h/2)

This is incomplete, the correct answer should be
divf_{i=0} = (f*_{im=0} - f*_{im=-1}) / (h/2)
BUT we do not have f*_{im=-1} at this point yet.

Later, after MPI communication is complete, the surf. RHS calculation adds

-f*_{im=-1}) / (h/2)

to divf_{i=0}. So that we now have
divf_{i=0} = (f*_{im=0} - f*_{im=-1}) / (h/2)

Note that f*_{im=-1} is computed from u_{i=0} and from u_adj which is
the u at the boundary of the node to the left (using e.g. LLF).

NOTE:  divf_{i=0} = (f*_{im=0} - f*_{im=-1}) / (h/2),  where:
 o x |   o   |   o   |   o   |   o   |   o   |   o
 |    \__
 |       \__
 |          \
f*_{im=-1}   f*_{im=0}
So divf_{i=0} is naturally located at x not o. For this reason
scalarwave1_surf_rhs_u calls rec1d_uface_to_uin_1 to interpolate
divf_{i=0} from the point x to the boundary point o using linear
interpolation
  ________
 | ^     ^
 v |     |
 o x     o       o       o       o       o       o

divf_{i=0} <-- w divf_{i=0} + (1-w) divf_{i=1}     where w=4/3

Recall:
 |u l|mW   pW|mW   pW|mW   pW|mW   pW|mW   pW|l u|
 o   |   o   |   o   |   o   |   o   |   o   |   o
     |
     f*_{im=0}
So f*_{im=0} has errors of O(h^2). Thus divf_{i=0} at x also has errors of
O(h^2). Since divf_{at x} = divf_{at o} + O(h), it is clear that if we set
divf_{at o} = divf_{at x} (i.e. if we just copy instead of interpolating)
our divf_{at o} would now contain an error of O(h). This is why we should
use linear interpolation, it keeps the error down to O(h^2).

 dx f^x  is naturally located at x
 dy f^y  is naturally located at o

BUT if:  fv_divf_extrap = divf_extrap1
---------------------------------------
fv_divf adds them both together to obtain
divf_{i=0,j=3} = dx f^x_{i=0} + dy f^y_{j=3}
(But this makes no sense as they are from different points!)
Later rec1d_uface_to_uin_1_mesh is called to interpolate divf_{i=0,j=3},
but this interpolation only makes sense for the  dx f^x  part, not for the
dy f^y  part. Probably we should make sure that only one (here dx f^x_{i=0})
is actually interpolated. Otherwise, if we interpolate terms like
dy f^y_{j=2} (which may have an error of only O(h^3)) we add errors of O(h),
because
 dy f^y_{i=1} = dy f^y_{i=0} + O(h).

If:  fv_divf_extrap = dnfn_extrap1
----------------------------------
*fv_divf computes the the full div including surface terms
 -this means we call get_all_surfaces(node) in fv_divf
 -fnumR[l][i] is extended so that for i=-1 we have flux at left face
 -fv_divf interpolates terms like  dx f^x  from x to o, and then adds them
  to divf. Then all terms are at facepoint o.
 -any interpolation in e.g. scalarwave1_surf_rhs_u is then switched off
*dg_add_surface_fluxes_sign skips fv nodes in this case

fv with non-Cartesian coordinates Xb = Xb(x)
============================================
Assume that we have just an advection equation
du/dt + df(u)/dx = 0  with f(u)=u.
Then if we set u=const we should always have du/dt = 0.

Of course we need to transform from x to Xb = \bar{X} coords.

Def: kb := \bar{k}  and  x^{kb} := \bar{X}^{\bar{k}}
     d       := \partial
     dx^i    := \partial x^i
     dx^{kb} := \partial x^{kb}

The normal along the x^{kb} coord line is then
n^{kb}_i = a dx^{kb}/dx^i

Here a is const determined from the normalization:
1 = \gamma^{ij} n^{kb}_i n^{kb}_j = a^2 dx^{kb}/dx^i \gamma^{ij} dx^{kb}/dx^j
Thus 1/a = \sqrt{dx^{kb}/dx^i \gamma^{ij} dx^{kb}/dx^j}
         =: \sqrt{\gamma^{kb,kb}

Def: M^{kb}_i := dx^{kb}/dx^i
     J        := 1/det(M^{kb}_i)
     f^{kb}   := dx^{kb}/dx^i f^i

Recall df^i/dx^i = (1/J) d(J f^{kb})/dx^{kb}
This comes from
df^i/dx^i = (1/\sqrt{\bar{\gamma}}) d(\sqrt{\bar{\gamma}} f^{kb})/dx^{kb}
where we note:
\bar{\gamma}_{ib,jb} = dx^i/dx^{ib} dx^j/dx^{jb} \delta_{ij}
==> det(\bar{\gamma}_{ib,jb}) = det( M^{-1} (M^{-1})^T ) = 1/det(M)^2
==> \sqrt{\bar{\gamma}} = \sqrt{det(\bar{\gamma}_{ib,jb})}
                        = 1/J

Now f^{kb} = dx^{kb}/dx^i f^i = (1/a) n^{kb}_i f^i
           = \sqrt{\gamma^{kb,kb} n^{kb}_i f^i
           = \sqrt{\gamma^{kb,kb} f
where we have define f := n^{kb}_i f^i
                     -----------------
So finally
  ------------------------------------------------------------------
  df^i/dx^i = (1/J) d(J \sqrt{\gamma^{kb,kb} f)/dx^{kb}        (1)
  ------------------------------------------------------------------

Numerically we compute this from
-------------------------------------------------------------
df^i/dx^i = (1/J_C) \sum_{kb}
            [ (J\sqrt{\gamma^{kb,kb})_R f^*_R           (A)
             +(J\sqrt{\gamma^{kb,kb})_L f^*_L ] / w
-------------------------------------------------------------

   o    |    o    |    o
        L    C    R

where f^*_R = (n^{kb}_i)_R f^{*i}_R,  f^*_L = (n^{kb}_i)_L f^{*i}_L
involve right and left pointing normals at the midpoints R and L.
w = h = distance between midpoints in Xb-coords

From the DG method we can also infer that instead of just f^* we should
use (f^* - f), where f is the actual inner flux at point C.
Then
---------------------------------------------------------------------
df^i/dx^i = (1/J_C) \sum_{kb}
            [ (J\sqrt{\gamma^{kb,kb})_R (f^*_R - f_R)           (B)
             +(J\sqrt{\gamma^{kb,kb})_L (f^*_L - f_L) ] / w
---------------------------------------------------------------------
where f_R = (n^{kb}_i)_R f^i_C,  f_L = (n^{kb}_i)_L f^i_C
and both involve the flux f^i at the same point C.

For Cartesian coords
J = \sqrt{\gamma^{kb,kb}) = 1, (n^{kb}_i)_R = (n^{kb}_i)_L = const
then f^i cancels out.

Test cases:
-----------
If f^i = (1,0,0) = const  ==>  n^{kb}_i f^i = n^{kb}_x
==> f_R   = (n^{kb}_x)_R,  f_L   = (n^{kb}_x)_L
    f^*_R = (n^{kb}_x)_R   f^*_L = (n^{kb}_x)_L

In the continuum case (1) is now
df^i/dx^i = (1/J) d(J \sqrt{\gamma^{kb,kb} n^{kb}_x)/dx^{kb}
          = df^i/dx^i = d(1)/dx^i + 0 = 0

coordinates_set_divb_J_sqrtgdiag_n computes this deriv numerically.

(B) says
df^i/dx^k = 0
as in the continuum limit.

(A) says
df^i/dx^i = (1/J_C) \sum_{kb}
            [ (J\sqrt{\gamma^{kb,kb})_R (n^{kb}_x)_R
             +(J\sqrt{\gamma^{kb,kb})_L (n^{kb}_x)_L ] / w
This converges to 0 with O(w)^2 = O(h)^2, since it approximates (1)
which is 0.

coordinates_set_ooJ_Db_J_sqrtgdiag_n and fv_test_fv_divf both compute
either (A) or (B).
We get (A) if par  fv_flux = fnum
We get (B) if par  fv_flux = fnum_minus_fi


Convergence test results for the scheme above
=============================================

WT has done fv-dg tests with scalarwave1 in 2d on Cartesian domains (see APS
talk 2022). It seems that we get 2nd order convergence or better. This is a
little surprising as we reconstruct like this:
 |u l|mW   pW|mW   pW|mW   pW|mW   pW|mW   pW|l u|
 o   |   o   |   o   |   o   |   o   |   o   |   o
I.e. on both ends there is a place (l) where we renstruct with only linear
interpolation. This might spoil 2nd order conv.

First tests with fv-dg on cubed spheres with scalarwave1 in 3d seemed to
show only 1st order conv. But it seems the problem comes from these two
pars (probably mostly the first one):
  fv_flux = fnum_minus_fi
  fv_surface_interp = parabolic
In src/tests/scalarwave1/parfiles/sw3dWENOZ.par we use:
  fv_rec = WENOmZ_2
  fv_flux = fnum
  fv_surface_interp = linear
  fv_divf_extrap = dnfn_extrap1
  fv_divf_extrap_s1 = 0.5
This works much better, and it looks like 2nd order convergent!!!


Flux reconstruction
===================

For GRHD we reconstruct the primitive variables on the midpoint and then
compute fluxes from them. Maybe it would be better to directly reconstruct
[ J\sqrt{\gamma^{kb,kb} (f^* - f) ] on the midpoints. This may be more
accurate, and then we do not need J and \sqrt{\gamma^{kb,kb} on the
midpoints at all.
Does anybody do flux reconstruction instead of primitive (or conservative)
variable reconstruction? Search literature...

Important fv parameters in main/dg/nmesh_dg.c
=============================================

fv_rec: how we reconstruct u at midpoint if we use fv
======
*In the interior we can reconstruct using WENO3, WENO5 or WENOZ.
*In our 1d shock tube tests WENOZ was better than WENO5 and WENO3.

Useful values for fv_rec
========================
-----------------
fv_rec = WENOmZ_2
-----------------
 0       1       2       3       4       5       6 <-- gridpoint number i
 |   |       |       |       |       |       |   |
 o x |   o   |   o   |   o   |   o   |   o   | x o
 |u l|mW   pW|mW   pW|mW   pW|mW   pW|mW   pW|l u|
  ^ ^ ^    ^  ^     ^ ^     ^
  | |  \  /    \   /   \   /
  | |  WENO3   WENOZ   WENOZ
  | linear interpolation using the gridpoints 0 and 1: l=(u_0 + u_1)/2
  value at gridpoint 0: u=u_0

-----------------
fv_rec = WENOmZ_1
-----------------
 0       1       2       3       4       5       6 <-- gridpoint number i
 |   |       |       |       |       |       |   |
 o x |   o   |   o   |   o   |   o   |   o   | x o
 |u u|mW   pW|mW   pW|mW   pW|mW   pW|mW   pW|l u|
  ^ ^ ^    ^  ^     ^ ^     ^
  | |  \  /    \   /   \   /
  | |  WENO3   WENOZ   WENOZ
  | value at gridpoint 0: u=u_0
  value at gridpoint 0: u=u_0

Once we have the u's on both sides of all midpoints, we compute the
numerical fluxes f*(u) at all midpoints.
Differences between adjacent numerical fluxes give divf at the points:
 | x |   o   |   o   |   o   |   o   |   o   | x |
But we need divf at the gridpoints:
 o   |   o   |   o   |   o   |   o   |   o   |   o
 0       1       2       3       4       5       6
Hence we have to decide how we get divf_{i=0} on the left o (at i=0) from x.
This is done with fv_divf_extrap*:

fv_divf_extrap*: how we extrapolate from x to o
===============

Useful values for fv_divf_extrap*
=================================
-------------------
fv_divf_extrap = no
-------------------
set divf_{i=0} = divf at x

----------------------------------
fv_divf_extrap     = dnfn_extrap1
fv_divf_extrap_s1  = 0
fv_divf_extrap_s2  = DBL_MAX
fv_divf_extrap_opt = 0
----------------------------------
set divf_{i=0} = w (divf at x) + (1-w) (divf at o)    where w=4/3

----------------------------------
fv_divf_extrap     = dnfn_extrap1
fv_divf_extrap_s1  = 0.5
fv_divf_extrap_s2  = 2.5
fv_divf_extrap_opt = 1
----------------------------------
set divf_{i=0} = w (divf at x) + (1-w) (divf at o)
where
    { 1    if |divf_1-divf_0|/|divf_2-divf_1| < 0.75 s1
w = { 1    if |divf_1-divf_0|/|divf_2-divf_1| > 0.75 s2
    { 1    if (divf_1-divf_0) and (divf_2-divf_1) have different signs
    { 3/4  otherwise


When dg and fv nodes meet, they usually do not have any surface gridpoints
in common. So we need to interpolate when we pass u values to the neighbor
node. This is determined by the par fv_surface_interp.

fv_surface_interp: how we interpolate within node surface
=================

Useful values for fv_surface_interp
===================================
--------------------------
fv_surface_interp = linear
--------------------------
*use linear interpolation in fv nodes, which is very robust if the fv
 node contains a shock
*use high order Lagrange interpolation in dg nodes, because they are not
 supposed to contain shocks

-----------------------------
fv_surface_interp = parabolic
-----------------------------
*use parabolic interpolation in fv nodes
*use high order Lagrange interpolation in dg nodes, because they are not
 supposed to contain shocks

FIXME: We should implement
fv_surface_interp = WENO4
*WENO4 should be more accurate and better for shocks than parabolic


Some observations with GRHD
===========================
*If fv_rec=WENOmZ_2 and fv_divf_extrap=dnfn_extrap1 we can expect 2nd order
 convergence at inter-node boundaries. All other options probably give only
 1st order convergence at inter-node boundaries.
*When all nodes are switched to fv and all have the same size and number of
 gridpoints and if fv_divf_extrap=no, then fv_rec=WENOmZ_1 conserves mass better
 than fv_rec=WENOmZ_2.
*BUT when dg and fv nodes meet, mass conservation gets a lot worse. In this
 case fv_rec=WENOmZ_2 seems to be a bit better.
 BUT maybe mass conservation could be improved if we implement
 fv_surface_interp=WENO4
*If we use fv_rec=WENOmZ_2 both fv_divf_extrap=dnfn_extrap1 and
 fv_divf_extrap=no perform about equally well in terms of mass conservation

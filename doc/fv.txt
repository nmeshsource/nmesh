How we can use finite volume (fv) in nmesh?
===========================================

Grid setup
==========

With standard dg we have non-uniform grid points in a node, e.g. like this:
o  o      o             o             o      o  o

For fv we 1st change the node grid points to e.g:
o       o       o       o       o       o       o

We then define midpoints (i.e. in the middle between grid points)
at which we need to need to reconstruct the fields so that we can get the
fluxes there. This would give:
o   |   o   |   o   |   o   |   o   |   o   |   o
                    <-- h -->
If d_t u = RHS = -d_x f
Then u at an interior point i, has a RHS of the following form:
RHS_i = -(f*_{i+1/2} - f*_{i-1/2})/h
here h is the distance between the 2 midpoints around point i.
                i
o   |   o   |   o   |   o   |   o   |   o   |   o
           /   u_i   \
          /           \
      f*_{i-1/2}       f*_{i+1/2}
Note, RHS_i is the quantity that would be the divergence of the flux in the
dg method.
RHS_i = -(f*_{i+1/2} - f*_{i-1/2})/h works for all interior points.

The points at the ends of the node are dealt with differently!
First we interpret the final points to be moved in by h/4, so that we get e.g.:
| x |   o   |   o   |   o   |   o   |   o   | x |
I.e. we now have another fv-element at the ends of the node.

So to update e.g. u_0, we now need the fluxes at f*_{1/2} and f*_{-1/2}:
d_t u_0 = RHS_0 = -(f*_{1/2} - f*_{-1/2})/(h/2)
| x |   o   |   o   |   o   |   o   |   o   | x |
|    \
|     f*_{1/2}
f*_{-1/2}
f*_{-1/2} can be constructed with the help from info from the node to the
left. f*_{1/2} can be constructed with information from within the node.


Flux reconstrution in the interior at e.g. at i+1/2
===================================================

*At 1st order (i.e. with error of O(h)):
Def:   up_{i+1/2} := u_{i}               um_{i+1/2} := u_{i+1}
       The function that gets up_{i+1/2} is rec1d_p_1.
Then:  fp_{i+1/2} = f(up_{i+1/2})        fm_{i+1/2} = f(um_{i+1/2})

fp_{i+1/2} and fm_{i+1/2} are two ways to reconstruct the flux at i+1/2.
In order to get the numerical flux f*_{i+1/2} we then use e.g. the LLF flux,
to calculate f*_{i+1/2} from
[inside: (up_{i+1/2}, fp_{i+1/2}), adjacent: (um_{i+1/2}, fm_{i+1/2})]

*At 3rd order (i.e. with error of O(h^3)):
Get fp_{i+1/2} and fm_{i+1/2} from e.g. rec1d_p_WENO3 and rec1d_m_WENO3.
Note: rec1d_p_WENO3 and rec1d_m_WENO3 only work if i>1 and i>0.
Again we can use e.g. LLF to get f*_{i+1/2}.

Flux reconstrution in the interior close to surface at e.g. at 1/2
==================================================================

*At 1st order (i.e. with error of O(h)):
Def:   up_{1/2} := u_{0}               um_{1/2} := u_{1}
       The function that gets up_{1/2} is rec1d_p_1.
Then:  fp_{1/2} = f(up_{1/2})        fm_{1/2} = f(um_{1/2})
Again we can use e.g. LLF to get f*_{i+1/2}.

Flux reconstrution at the node surface e.g. at -1/2
===================================================

*At 1st order (i.e. with error of O(h)):
Def:   up_{-1/2} := u_adj <- val from node to left
Def:   um_{-1/2} := u_{0}
       The function that gets um_{-1/2} is rec1d_p_1, u_adj it sent via MPI.
Then:  fp_{-1/2} = f(up_{-1/2})        fm_{-1/2} = f(um_{-1/2})
Again we can use e.g. LLF to get f*_{-1/2}.
[inside: (um_{-1/2}, fm_{-1/2}), adjacent: (up_{-1/2}, fp_{-1/2})]

= Some more notes about fv and WENOm3_2 =
=========================================
First of all, WENO works much better on a uniform grid. That is why

      if(DGglobals->fv_rec_mode >= FV_REC_WENO3if2away_1)
        rec1d_uface_to_uin_1(node, vlu, 1);

in scalarwave1_set_divf is usually inactive before calling fv_divf. I.e. we
do not interpolate to the point x first.
o x |   o       o       o       o       o       o

Rather we keep the grid as:
 0       1       2       3       4       5       6 <-- gridpoint number i
 o   |   o   |   o   |   o   |   o   |   o   |   o
     0       1       2       3       4       5     <-- midpoint number im
-1                                               6 <-- facepoints: im=-1, im=6

We can use e.g. rec1d_p_WENOm3_2 and rec1d_m_WENOm3_2 to reconstruct u at the
interior midpoints from the points to the left and right. Points near or at
the boundary are more complicated.  We can reconstruct like this:

 |u l|mW   pW|mW   pW|mW   pW|mW   pW|mW   pW|l u|
 o   |   o   |   o   |   o   |   o   |   o   |   o

Here:
 -pW: use rec1d_p_WENOm3_2 to reconstruct u
 -mW: use rec1d_m_WENOm3_2 to reconstruct u
 -l: use linear interpolation using the gridpoints (o) to the left and right
 -u: use the value of u at the gridpoint (o) at the node boundary

So for interior midpoints (im=0-5) we have a left and right value for u,
i.e. up and um. From these 2 we can then get the 2 fluxes fp and fm.
From fp and fm we calculate the numerical flux f* using e.g. LLF.
Then we have:
i=0     i=1     i=2     ...
 o   |   o   |   o   |   o   |   o   |   o   |   o
    /        \
   /          \
 f*_{im=0}   f*_{im=1}   ...

From f* at (im=0-5) we can then get divf = dx f on all interior
gridpoints (i=1-5). I.e. for i=1,2,...,5 we use:

divf_{i} = (f*_{im} - f*_{im-1})/h ,    where im = i.


The boundary gridpoints (i=0 and i=6) are different:
----------------------------------------------------
The vol RHS calculation calls fv_divf which sets

divf_{i=0} = f*_{im=0} / (h/2)

This is incomplete, the correct answer should be
divf_{i=0} = (f*_{im=0} - f*_{im=-1}) / (h/2)
BUT we do not have f*_{im=-1} at this point yet.

Later, after MPI communication is complete, the surf. RHS calculation adds

-f*_{im=-1}) / (h/2)

to divf_{i=0}. So that we now have
divf_{i=0} = (f*_{im=0} - f*_{im=-1}) / (h/2)

Note that f*_{im=-1} is computed from u_{i=0} and from u_adj which is
the u at the boundary of the node to the left (using e.g. LLF).

NOTE:  divf_{i=0} = (f*_{im=0} - f*_{im=-1}) / (h/2),  where:
 o x |   o   |   o   |   o   |   o   |   o   |   o
 |    \__
 |       \__
 |          \
f*_{im=-1}   f*_{im=0}
So divf_{i=0} is naturally located at x not o. For this reason
scalarwave1_surf_rhs_u calls rec1d_uface_to_uin_1 to interpolate
divf_{i=0} from the point x to the boundary point o using linear
interpolation
  ________
 | ^     ^
 v |     |
 o x     o       o       o       o       o       o

divf_{i=0} <-- w divf_{i=0} + (1-w) divf_{i=1}     where w=4/3

Recall:
 |u l|mW   pW|mW   pW|mW   pW|mW   pW|mW   pW|l u|
 o   |   o   |   o   |   o   |   o   |   o   |   o
     |
     f*_{im=0}
So f*_{im=0} has errors of O(h^2). Thus divf_{i=0} at x also has errors of
O(h^2). Since divf_{at x} = divf_{at o} + O(h), it is clear that if we set
divf_{at o} = divf_{at x} (i.e. if we just copy instead of interpolating)
our divf_{at o} would now contain an error of O(h). This is why we should
use linear interpolation, it keeps the error down to O(h^2).

Reconstructing u at -, -- and | can be done as in the 1D case.
But now:
 dx f^x  is naturally located at x
 dy f^y  is naturally located at o

BUT if:  fv_divf_extrap = divf_extrap1
---------------------------------------
fv_divf adds them both together to obtain
divf_{i=0,j=3} = dx f^x_{i=0} + dy f^y_{j=3}
(But this makes no sense as they are from different points!)
Later rec1d_uface_to_uin_1_mesh is called to interpolate divf_{i=0,j=3},
but this interpolation only makes sense for the  dx f^x  part, not for the
dy f^y  part. Probably we should make sure that only one (here dx f^x_{i=0})
is actually interpolated. Otherwise, if we interpolate terms like
dy f^y_{j=2} (which may have an error of only O(h^3)) we add errors of O(h),
because
 dy f^y_{i=1} = dy f^y_{i=0} + O(h).

If:  fv_divf_extrap = dnfn_extrap1
----------------------------------
*fv_divf computes the the full div including surface terms
 -this means we call get_all_surfaces(node) in fv_divf
 -fnumR[l][i] is extended so that for i=-1 we have flux at left face
 -fv_divf interpolates terms like  dx f^x  from x to o, and then adds them
  to divf. Then all terms are at facepoint o.
 -any interpolation in e.g. scalarwave1_surf_rhs_u is then switched off
*dg_add_surface_fluxes_sign skips fv nodes in this case

fv with non-Cartesian coordinates X = X(x)
==========================================
Assume that we have just an advection equation
d_t u + d_x f(u) = 0  with f(u)=u.
Then if we set u=const we should always have d_t u =0.

When we compute on the X-grid, we need to take differences like
RHS = -(f*_{i+1/2} sqrtgdiag / w - f*_{i-1/2} sqrtgdiag / w).
Here
w         = distance between midpoints in X-coords and
sqrtgdiag = \sqrt{\gamma^{\bar{i}\bar{i}}}, i.e. the sqrt of the diagonal
            components of upper index 3-metric in Xb-coords.

Since the fluxes f*_{i+1/2} and f*_{i-1/2} are reconstructed at midpoints
one may think that sqrtgdiag (and any normals one may need) should also be
the ones at these midpoints. In our example with u=const in the advection
equation we get f*=const. But sqrtgdiag will be different on midpoint i-1/2
and i+1/2. Thus RHS will not be 0!!! This is bad!
So I expect that both sqrtgdiag factors in
RHS = -(f*_{i+1/2} sqrtgdiag / w - f*_{i-1/2} sqrtgdiag / w)
as well as any normals we need should be computed at gridpoint i, and NOT at
the midpoints!!!

Some time ago we introduced the par coordinates_midpoint_data, so that we
can have dX/dx on X midpoints. From this we can then get sqrtgdiag, or the
normals at the midpoints. It seems this should never be used!!!

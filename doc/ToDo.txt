MPI parallelization plans

Plan1:
------
*make ghosts in s[6] of dat be the values obtained from the neighbor node.
 E.g. s[2][i] may have var i from neighbor node in -Y dir.
 s[2][i] then has e.g. n[0]=n[2]=4 (if nb has 4 points in X and Z dirs) and:
*make 2d-array for u_other and use data in s to interpolate into u_other
*the node and each nb has to interpolate onto 16 points, load is balanced
*use u and u_other to set another 2d-array for flux
*use flux for time step
*this way each node only sends its own data on the surface, if e.g. 4 nb face
 one node (and each has n[0]=n[1]=4):
 node sends 4*16 points and 4 nb send 4*16 points
-> load is balanced, 8*16 points are sent

Plan0:
------
*make ghosts in s[6] of dat be the values interpolated by neighbor node.
 E.g. s[2][i] may have INTERPOLATED var i from neighbor node in -Y dir.
 s[2][i] then has e.g. n[0]=n[2]=4 (if nb has 4 points in X and Z dirs) and:
*then u_other = s
*use u and u_other to set another 2d-array for flux
*use flux for time step
*this way each node only sends interpolated data, if e.g. 4 nb face
 one node (and each has n[0]=n[2]=4):
 node sends 4*16 points and 4 nb send 4*4 points
*node needs to interpolate values to 4*16 points
*each of the 4 nb has to interpolate only to 4 points (not balanced)
-> load is not balanced, node interpolates and sends more, 5*16 points are sent

=> Plan1 is more balanced, but Plan0 sends less

=> in nmesh I went for Plan1!!!
